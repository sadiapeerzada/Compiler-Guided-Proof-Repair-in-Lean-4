# Proposed future experiment — requires separate authorization

Status: protocol proposal only, not preregistered, not executed. Existing sparse and overlapping evidence leaves diagnostic-content benefit unresolved. A new experiment is scientifically justified only after independent benchmark construction and validation.

Independent mathematicians should construct and kernel-validate 240 new theorem types from specified source strata, with human-written English and independent semantic review. Deduplicate against all previously inspected development/test items and partition mathematical families before model access. Use a separate 40-theorem development pool; keep new test statements inaccessible during prompt selection. Reviewers sign the frozen test manifest, references and partition rationale. If a validated disjoint pool cannot be assembled, do not start. Freeze model revision, Lean/mathlib versions, prompts and tokenization.

Predeclare seeds 2037/2038/2039. Generate one initial candidate per theorem/seed and use precisely the same failed predecessor for real compiler feedback, shuffled feedback and neutral feedback. Initial successes remain in the cohort and are reported separately; the primary endpoint is first-repair strict kernel verification among initial failures. No sorry/axiom bypasses or substituted reference proofs. Match all repair prompts to the same tokenizer-count budget using predeclared neutral padding; diagnostics have a frozen truncation limit. Shuffle diagnostics from disjoint theorem donors using a frozen map with no own-diagnostic matches. Randomize arm order within theorem/seed and counterbalance machine/time blocks. One repair call per arm, same decoding settings/output cap. No retries except predeclared infrastructure recovery preserving intent and candidate hashes.

Primary contrast: real minus shuffled first-repair success, theorem-clustered across all three seeds; neutral is a secondary comparison with Holm adjustment for the two declared comparisons if inferential claims involve both. Report full-cohort and initial-failure denominators, paired discordance, incomplete bounds, theorem/family sensitivity intervals and confidence intervals. Resample theorem clusters with all seeds (20,000 replicates; seed 2037001); adjudicate any cross-theorem dependence before unblinding outcomes. Do not replace missing outcomes with failures without bounds. Freeze the analysis script on development-only synthetic fixtures before test access.

Precision feasibility: for independent theorem-level means of paired binary differences in [−1,1], the conservative variance bound is 1. A normal-approximation 95% half-width at 240 independent theorem types is at most approximately 1.96/sqrt(240)=12.7 percentage points; three correlated seeds do not triple the sample. With an assumed paired discordance probability 0.20 and perfect within-theorem seed dependence, approximate half-width is 5.7 points; roughly 628 theorem types would be needed for 80% power for a 5-point effect using the rough formula (1.96+0.84)^2*0.20/0.05^2. These are planning assumptions, not guaranteed power or analysis results. Family dependence, initial successes and missingness worsen precision. If 240 types cannot meet the desired precision, label this a pilot or enlarge the independent pool before freezing; never use observed test wins to select extra examples.

Hard compute budget: 720 initial calls plus at most 2,160 first-repair calls, total 2,880; cap each input at 4,096 tokens and output at 1,200 (upper allocation 11,796,480 input and 3,456,000 output tokens). Hardware throughput/cost must be measured on development cases and a wall-clock allocation approved before execution; no monetary estimate is asserted. Stop at the call/token caps or a predeclared 48-hour allocation, whichever comes first. Stop for invalid benchmark/provenance or systematic verifier failure; report incomplete outcomes and do not expand the budget after inspecting performance. No efficacy-based early stopping.

Multi-step work, if separately authorized, must be declared a policy comparison: predecessor histories diverge after step one, requiring separate endpoints and interpretation. Do not reuse these newly observed test items as a new confirmatory set later.
